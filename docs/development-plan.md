# 자동 이착륙 및 비행 모델 개발 계획

## 다음 계획 — 2026-11-19

사용자가 추진 정밀화·지상 물리 정밀화·비행 영역 확장·운용 범위/정식 시험을 요청했다. [P0~P6 후속 계획](physics-expansion-plan.md)에 자료/시험 기준 확정 → 프로펠러/거버너 → 후류 → 완충/타이어 → 비대칭 실속/스핀/버핏/연료·CG → 통합 운용 → 공식 시험/인수를 정리했다. **현재는 계획이며 구현/시험 완료가 아니다.** 연구 가정의 구현, 프로젝트 소프트웨어 공식 시험, 실기체 성능 대조를 별도 판정한다.

## 현재 우선순위 — 2026-11-18

사용자 후속 승인으로 보류했던 항법과 물리 정밀화를 함께 진행했다. **기준 진단 → 항로/러더+추진 개선 → 바퀴별 지형/타이어+저속 운항 → 실제 지형 왕복**의 연구 범위를 마쳤다. 코어15/15·실제 API19검사·무풍/작은 바람20km 왕복과 기록/표시 검사가 통과했다. [수식·기준 비교·남은 자료/물리 범위](navigation-physics.md)가 아래 이전 계획보다 현재 상태에 우선한다. 실측 CT/CQ·거버너/후류·완충·정식 성능 시험은 완료에 포함하지 않는다.

### 이전 M0~M5 계획·결과

사용자 요청으로 [연속 귀환·착륙과 기체 동작 개선 계획](return-landing-plan.md)을 우선한다. **착륙 전환 문제 진단/수정 → 실제 지형의 중간 초기화 없는 왕복 → 외형·추진·지상 정합/정밀화 → 변경 후 연속 시연 마감** 순서다. 일반 근접 측방 항로점 포착 개선·이상적 선회식 잔차 분석·러더 협조 제어는 이후로 미룬다. 착륙 단계의 불안정한 경로/뱅크 전환 수정은 현재 우선 범위다.

M0~M5의 연구 개발 범위를 구현했다. 귀환·고도 처리·형상/감속·정렬과 진단 UI/API, 실제 지형 연속 왕복, 형상/접촉 정합·추력선 모멘트·지상 응답을 연결했다. CTest12/12·UE5.8.4 빌드·관련 실제 API173검사가 통과했다. [실제 조건·실패 보존·비교 결과·남은 범위](return-landing-results.md)를 따른다. 실측 성능 검증과 보류한 일반 항법/러더 작업은 완료에 포함하지 않는다. 아래는 이전 작업의 기록이다.

## 이전 작업 기록

완료한 작업 계획(2026-11-17): [비행시험 기록·비교](flight-test-plan.md). 카메라 수정 빌드 마감 → C208B 65m/s 엘리베이터 짧은 입력 → CSV/메타데이터/그래프·재현/독립 계산 → 다른 입력·선회/활공/플랩 → 한 매개변수 민감도 비교 순서다. 기록기·오프라인 보고서·CSV/JSON·비교와 시험 종류 구현 및 최종13회 실제 기록시험·재현·관성 비교·Thor 회귀를 완료했다. 사용자 지시에 따라 Unreal/API/보조 프로세스를 종료했다. [사용법·실제 검사 기록](flight-tests.md)을 기준으로 계획과 실행 결과를 구분한다.

2026-11-17 실행 결과: 사용자 승인으로 **B와 C~F의 별도 C208B 연구 가정 범위**를 구현했다. CTest10/10·UE5.8.4 빌드·기존 API30개·연구 API 검사가 통과했다. [실제 단계별 상태](fixed-wing-expansion.md), [사용법·미구현 물리](c208b-research.md). A2 동일 구성 실기체 자료 확보와 실제 성능 대조는 미완료이며 아래 실기체 자료 기반 계획을 대신 통과했다고 표현하지 않는다.

2026-11-17 최종 지정: **첫 대형 비행역학 기준은 Cessna 208B Super Cargomaster**, **후속 쌍발 후보는 King Air 350**이다. 기존 200kg 초과 단발 무인기 후보 탐색에서 유인 단발 터보프롭을 계산 코어의 기준으로 쓰는 방향으로 변경했다. 아래 1~11번은 기존 Thor 개발 범위의 상태이며 C208B 지원 완료를 뜻하지 않는다. 기체명 지정(A1)은 완료했고 동일 연구 구성의 자료 확정(A2)은 미완료다. B와 별도 연구 가정의 C~F는 구현됐으며, 실기체 자료 기반 후속 작업은 A2 미확보 자료와 독립 성능 비교 기준 확정이다. 현재 선택 파일은 C208B 연구 모델을 사용한다.

작업 순서는 [확장 계획](fixed-wing-expansion.md)의 **A1 지정/A2 자료 확정 → B 초기화 → C1 clean 국소 공중 모델 → C2 터보프롭·형상 → D 고정기어 지상 → E1 항로/E2 자동 왕복 → F Thor/C208B 적용 마감**이다. B, 공중 모델, 전체 운용 개발 모델의 종료선을 구분하고 단계별 최소 검사·자료 부족·실패 처리 기준을 따른다. 실기체 저속 공력/접지 자료가 없으면 실기체 성능을 검증한 자동 이착륙으로 표시하지 않는다. 사용자 승인한 별도 연구 모델의 공중·지상·자동 운항 구현과 구분한다. King Air 350의 쌍발·엔진아웃은 이번 범위에서 제외한다.

2026-09-13 사용자 요청. IMU·GNSS 항법 센서와 외부 비행제어컴퓨터 연동은 제외한다. 후속 요청에 따라 EO/IR 장면 영상·짐벌·가상 표적 지향을 별도로 추가한다. 제품의 Python API는 계속 제공하며 외부 FDM 구현은 사용하지 않는다.

새 공력·추진·착륙장치 계수를 실측값으로 간주하지 않는다. 자동 이착륙은 현재 소형 고정익 개발 모델과 가상 시험 활주로에서 검증한다. 정식 신뢰성·정적·동적 시험, 실제 기체 성능 일치, 스핀·비대칭 실속·버핏 등은 별도의 실측 근거와 합격 기준이 필요하다.

코어 검사 → Unreal 빌드 → 실제 API 운용 검사 순으로 실행하고, 코드 변경이나 실패가 없는 검사는 반복하지 않는다. 결과와 남은 범위는 이 문서에 갱신한다.

공개 API의 기준은 [API 사용 매뉴얼](api-reference.md)이다. API 변경 때 endpoint·Python 클라이언트·해당 Web UI·매뉴얼 예제와 상태·검사 기록을 같은 작업에서 갱신하고 목록·링크를 대조한다. 별도 정기 자동화를 만들지 않는다.

- 별도 명령으로 600m 후방/60m 높이에 놓은 최종 접근 시험은 약 42.32초 후 주차 완료했다. 이 시험 위치 초기화는 자동 제어와 분리된 명시적 명령이다.
- 왕복 착륙의 법선 접지 속도는 약 .57m/s였고, 착륙 활주 관측 위치는 활주로 시작점부터 약 113m로 설정 폭·길이 안이었다. 수치는 현재 개발 모델의 계산 결과다.
- 엔진 시간상수 .30초→.60초의 JSON 교체에 따라 .30초 후 출력이 각각 `1-exp(-1)`→`1-exp(-.5)`와 일치했다. 잘못된 질량은 기존 모델·물리 상태를 보존하며 거부했다. 고착된 조종면과 엔진 출력 상실, 시간 지정 돌풍의 재현을 확인했다.
- 독립 코어에서는 2m/s 횡풍 왕복 이착륙, 불안정 최종 접근의 복행, 이륙 활주 중 엔진 정지 후 제동도 통과했다. 접촉 박리량을 중복 적분하던 횡풍 수치 오류를 수정하고 회귀 검사를 남겼다.

## 남은 물리 확장

STL 외형 교체는 공력·관성·접촉 형상을 생성하지 않는다. 내장 1.27m 기체의 바퀴·동체 접촉점은 그대로이며, 단일 STL의 조종면·기어 애니메이션에는 별도 부품·힌지 정의가 필요하다. 파일 계약은 [STL 외형 안내](aircraft-model.md)를 따른다.

기어는 시뮬레이션 시간 3초 전환과 완전 전개 접촉, 개발 항력 차이만 반영한다. 자동 이륙은 10m 이상 상승 중 수납하고 착륙은 전개한다. 문·유압·개별 기어 고장·실측 수납 형상은 아직 없다. 이는 실제 Thor의 수납식 착륙장치를 검증했다는 뜻이 아니다.

실제 모터/RPM/프로펠러 후류, 서보별 실측 응답, 착륙장치 완충·타이어 슬립, 비대칭 실속·스핀·버핏과 실측 전 영역 공력 테이블은 아직 없다. 지금 값은 파일로 교체·시험할 수 있게 했으며, 실측 자료를 확보하면 해당 모델을 순서대로 보정한다. 새 데이터를 임의로 꾸며 상용 또는 인증 수준이라고 표현하지 않는다. IMU·GNSS 항법 센서와 외부 비행제어컴퓨터 연동은 제외 결정을 유지한다. EO/IR 표시의 별도 범위와 한계는 [EO/IR 안내](eoir.md)를 따른다.
