# 지상 활주·수동 이착륙

자체 비행역학에 3개 바퀴의 지면 접촉·마찰, 앞바퀴 조향, 브레이크·주차 브레이크와 기어 전개·수납을 연결했다. 같은 기체 상태로 활주에서 비행, 착지와 정지까지 이어진다. Web UI와 외부 Python은 같은 API를 사용한다. 전체 계약은 [API 사용 매뉴얼](api-reference.md), 별도 개발 제어기는 [자동 이착륙 안내](automatic-flight.md)를 따른다. 공중 항로점 API로 지상 이륙을 지시하지 않는다.

## Web UI에서 시작

1. Unreal 실행과 지형 준비가 끝나면 **지상 시작**을 누른다. 첫 가상 시험 활주로 시작점 안쪽 30m에 기체를 놓고 무추력·지상속도 0·주차 브레이크 상태로 정지한다. UI는 1배속과 기체 추적으로 전환한다.
2. 첫 조작은 무풍·1배속에서 한다. 조종면을 중립으로 놓고 주차·일반 브레이크를 해제한다. 스로틀을 100%로 올리고 **비행 재생**을 누른다. 앞바퀴 조향은 저속에서 조금씩 적용한다. 양수는 오른쪽이다.
3. 현재 개발 모델의 예제로 **TAS 11m/s 이상**에서 엘리베이터 **−6°**를 적용해 기수를 든다. 바퀴 접촉이 사라지고 상승하면 엘리베이터 당김을 줄이며 받음각·속도를 확인한다. −6°를 계속 유지하면 과도하게 기수를 들고 실속할 수 있다.
4. 착륙은 사용자가 방향·속도·침하율을 조절해 활주로에 접근한다. 착지 후 추력을 줄이고 브레이크로 감속한다. 위 이륙 수치는 조작 예시이며 실제 Thor의 이륙 속도나 검증된 운용 절차가 아니다.

동체·날개 접촉 또는 **지면 법선 접근속도 4m/s 초과**의 바퀴 접촉은 충돌로 기록하고 정지한다. 이는 개발 기준이며 인증된 착륙장치 한계가 아니다. `ground.crashed=true` 상태는 재생으로 해제되지 않는다. **지상 시작** 또는 새 초기 조건으로 복구한다. 기존 **초기화**는 현재 계산 원점의 타원체고 2600m/19m/s 공중 트림으로 돌아간다.

활주로가 정의되지 않은 지도에서 지상 시작은 현재 계산 원점의 지면을 사용한다. 지면이 없으면 요청을 거부한다. 현재 바람은 지상 초기화 후에도 유지한다.

## Python API

API 서버와 Unreal이 준비된 뒤 다음 코드로 무풍 활주를 시작한다.

```python
from uavsim_client import UAVSimClient

sim = UAVSimClient()
sim.reset_on_ground()
sim.set_time_scale(1)
sim.set_view("aircraft")
sim.set_wind(wind_east_mps=0, wind_north_mps=0, wind_up_mps=0)
sim.set_ground_controls(steering_deg=0, brake=0, parking_brake=False)
sim.set_controls(elevator_deg=0, aileron_deg=0, rudder_deg=0, throttle=1)
sim.set_running(True)
state = sim.get_state()
print(state["aircraft"]["speed_mps"], state["ground"])
```

TAS가 11m/s 이상임을 확인한 뒤 아래 호출로 기수를 들고, 이륙 후 당김을 줄인다. 이 호출 자체는 이륙 감지나 자세 유지를 수행하지 않는다.

```python
sim.set_controls(elevator_deg=-6, aileron_deg=0, rudder_deg=0, throttle=1)
# 이후 받음각·상승·바퀴 접촉 상태를 보면서 elevator_deg를 조절한다.
```

정지 상태에서 외부 프레임워크가 `sim.step(.01)`로 시간과 입력을 명시해 진행할 수도 있다. 접촉 동작도 같은 코어를 사용하며 배속은 명시적 step에 곱하지 않는다.

| HTTP 경로 (`/api/v1` 기준) | 요청과 동작 |
| --- | --- |
| `PUT /ground-controls` | `steering_deg` −30~30°, `brake` 0~1, `parking_brake` bool을 모두 지정. 기존 비행 조종 입력 4개는 유지하고 항법을 해제한다. |
| `PUT /gear` | `down` bool. `set_landing_gear(down=True)`로 전개, false로 수납. 목표만 바꾸며 실제 행정은 시뮬레이션 3초다. |
| `POST /ground/reset` | `{}`. 첫 시험 활주로 출발점 또는 현재 원점 지면에 속도·추력·시간·거리 0, 주차 브레이크, 정지 상태로 배치한다. |
| `PUT /ground/initial-condition` | `latitude_deg` −90~90°, `longitude_deg` −180~180°, `heading_deg` −360~360°, `ground_speed_mps` 0~15m/s를 모두 지정. 지면에서 높이·자세를 계산하고 항법·시간·거리·조종 입력을 초기화하며 정지한다. 지상속도 0일 때 주차 브레이크를 켠다. |

방위각은 북쪽 0°에서 시계방향이다. 초기 지상속도는 선택한 방위의 지면 접선 방향 속도이며 TAS가 아니다. 상태의 `aircraft.ground_speed_mps`는 ENU 수평 지상속도이고 `aircraft.speed_mps`는 TAS다. 초기 속도 상한은 현재 입력 범위이며 기체 성능 한계가 아니다. 모든 필드는 정확한 이름으로 보내며 알 수 없는 필드·범위 밖 숫자는 HTTP 400, 지면 누락·충돌 상태 등으로 거부된 명령은 409다.

임의 지상 위치를 지정하는 예제는 다음과 같다. 지형·활주로에 맞춰 높이와 자세를 계산하므로 타원체고·피치·롤을 전달하지 않는다.

```python
sim.set_ground_initial_condition(
    latitude_deg=33.509, longitude_deg=126.49,
    heading_deg=60, ground_speed_mps=0)
```

## 지상 상태

`gear`는 지상 입력과 별도 객체다. `command_down`은 목표, `extension`은 0~1 실제 전개율, `down_locked`·`up_locked`는 목표와 끝점이 일치하는 잠금, `moving`은 목표까지 미완료 상태다. 초기화는 완전 전개다. 정지 중 목표 변경 후 `step` 또는 재생으로 진행하며 중간 반전도 가능하다. 일반 비행 조종 입력은 기어를 바꾸지 않는다.

지상 수납, fault·지형 미준비 상태, 활성 자동 이착륙 중 수동 기어 명령은 거부한다. 수동 착륙 전에 전개를 명령하고 `down_locked=true`를 확인한다. 완전 전개 잠금 전에는 바퀴가 하중을 지지하지 않으며 동체·날개 충돌은 계속 판정한다. 수납 상태로 지면에 닿는 것은 정상 착륙으로 처리하지 않는다.

모든 비행 상태 응답에 다음 `ground` 객체를 포함한다. 값은 센서 관측이 아닌 계산 상태다.

| 필드 | 의미 |
| --- | --- |
| `available` | 현재 위치에서 지면을 조회할 수 있는지. false이면 높이 0 지면을 추정하지 않으며 높이 필드의 0을 실제 고도로 해석하지 않는다. |
| `on_ground`, `wheels_on_ground` | 바퀴 접촉 여부와 접촉 바퀴 수(0~3). 동체 충돌 여부는 `crashed`에서 확인한다. |
| `height_agl_m` | CG에서 조회한 지면 평면까지 **부호 있는 법선 거리(m)**. 수직 고도나 바퀴 간격이 아니다. 평평한 지면에 정지한 기본 형상에서는 약 .18m다. |
| `terrain_height_m` | 조회한 지형·활주로·갓길 접촉면의 WGS84 타원체고(m). 정표고와 다르다. |
| `normal_force_n` | 마지막 접촉 계산 간격에서 바퀴 법선 충격량 합을 간격으로 나눈 반력(N). 최초 지상 배치는 정적 중량 성분으로 초기화한다. 스트럿의 최대 충격 하중이나 계측 센서값이 아니다. |
| `impact_speed_mps` | 최근 접지의 최대 지면 법선 접근속도(m/s). 수직속도와 다르며 접지 후에도 기록을 유지한다. |
| `crashed` | 동체·날개 접촉 또는 개발 접지 한계 초과가 기록된 상태. 초기 조건을 다시 지정할 때 해제한다. |
| `steering_deg`, `brake`, `parking_brake` | 적용된 앞바퀴 조향각·브레이크·주차 브레이크 입력. |
| `surface` | `terrain`, `development runway shoulder` 또는 설정한 활주로 이름. |

`aircraft.load_factor`는 공력 하중계수이며 접촉 반력을 포함하지 않는다. 지상 하중은 `ground.normal_force_n`을 별도로 읽는다. 충돌 시 요청한 step 전체 시간까지 진행하지 않고 충돌 시점에서 멈출 수 있으므로 반환된 시뮬레이션 시간을 확인한다.

## 가상 시험 활주로 설정

활성 `terrain.json`과 같은 폴더의 선택적 `runways.json`을 읽는다. 현재 `maps/korea/runways.json`은 다음 가상 제주 시험 활주로를 지정한다. 실제 제주공항의 위치·고도·형상을 재현한 시설이 아니다.

```json
{
  "runways": [
    {
      "name": "Jeju development strip (virtual)",
      "latitude_deg": 33.509,
      "longitude_deg": 126.49,
      "heading_deg": 60,
      "length_m": 1000,
      "width_m": 40
    }
  ]
}
```

위경도는 활주로 중심, 방위는 북쪽에서 시계방향이다. 길이 100~3000m, 폭 10~100m, 방위 ±360°를 받는다. 최대 16개, 파일 크기 64KiB이며 이름은 비어 있지 않은 120자 이하다. 활주로 중심의 국소 수평면에 인공 평탄면을 만들고 바깥 둘레에 **20m 폭 갓길**로 원래 지형까지 연결한다. 표시와 접촉에 같은 면을 사용한다.

기본 높이는 활주로 길이를 최대 5m 간격으로, 폭 방향을 양 끝·중앙에서 샘플한 지형 최대값보다 .25m 위다. 최대값은 활주로 중심의 법선 기준으로 구한다. 선택적 `ellipsoid_height_m`은 중심의 WGS84 타원체고이며 이 샘플 최대값보다 최소 .1m 위, 20000m 이하여야 한다. 이는 샘플 기반 배치이며 모든 실제 지형 돌출부를 조사한 결과가 아니다. 활주로·갓길에 지형이 누락되면 로드를 거부한다.

수정 후 **지도 다시 읽기** 또는 `sim.reload_terrain()`을 호출한다. 실패하면 이전 지도·기체 위치를 유지하고 정지하며 `terrain.error`를 반환한다. 성공 후 **지상 시작**으로 첫 활주로에 배치한다. 지도 파일 준비는 [maps.md](maps.md)를 따른다.

## 계산 가정과 한계

`Source/FlightCore/GroundContact.h`의 앞바퀴 1개·주바퀴 2개가 완전히 전개·잠금됐을 때 강체 접촉점으로 작동하며, `FixedWing.h`에서 비관통 법선 충격량과 마찰을 계산한다. 완전 전개 바퀴 위치(FRD m)는 `(.35,0,.18)`, `(-.12,-.22,.18)`, `(-.12,.22,.18)`이다. 구름 마찰 .025, 제동 마찰 .70, 횡마찰 .80과 최대 .002초 접촉 간격·12회 반복 계산을 사용한다. 이 값과 4m/s 충돌 기준은 실측 Thor 착륙장치 자료가 없는 **개발 가정**이다. 내장 표시 외형과 접촉 모델은 기본 Thor 설정의 1.27m 날개폭을 기준으로 하며, 프로필에서 공력 날개폭을 바꾸어도 형상은 자동 변경되지 않는다. [STL 외형](aircraft-model.md)으로 표시를 바꾸어도 이 접촉점과 충돌 기준은 유지한다.

세 기어는 3초에 함께 전환하며 렌더 힌지를 최대 90° 접고 완전 수납 메시를 숨긴다. 기존 완전 전개 공력을 기준으로 `Cd=max(0, 기존 Cd+.012*(extension-1))`를 사용한다. 전환 시간·항력 상수는 코어의 개발 가정이며 기체 프로필 50개 항목에는 추가하지 않았다. 중간 기어의 바퀴 접촉이나 도어·유압·개별 기어 고장은 모델링하지 않는다.

기어 추가 후 Unreal Development 빌드·Release CTest 7/7과 실제 [기어 API 21/21 검사](../artifacts/gear-api-check.json)가 통과했다. 지상 수납 거부·3초 이동·반전·수납 접지의 동체 충돌과 native 속성 조회에 의한 전개/중간/수납 힌지 표시를 확인했다. 실행 명령은 `scripts/check-gear-api.py --impact`이며 실제 기체·위치·시간을 바꾼다. 종료 시 지상 주차·전개·1배속·정지로 복구한다. 전체 사용법과 기록은 [API 매뉴얼](api-reference.md)을 따른다.

Unreal 어댑터는 현재 기체 아래의 지형 삼각형 또는 활주로에서 국소 평면을 만들고 코어에 전달한다. 바퀴마다 서로 다른 지형 면을 별도 조회하지 않는다. 동체·날개 충돌은 대표 점 6개로 판정하므로 모든 표시 형상의 연속 충돌을 보장하지 않는다. 기본 전국 지형은 수백 m 간격의 단순화된 DSM이며 실제 활주면 요철·공항 포장 상태를 재현하지 않는다.

완충장치 스트로크·스프링·댐퍼, 바퀴 회전·타이어 변형·정밀 슬립, 차등 브레이크·안티스키드, 착륙장치 파손, 지면효과, 센서 모델은 없다. 비행 조종면의 서보 응답·고착과 엔진 지연·출력 상실은 [기체 시스템 모델](aircraft-profile.md)에 구현했다. 브레이크는 모든 바퀴에 적용하는 개발 근사다. 물/육지 구분 마스크도 아직 없으므로 바다를 포함한 지형 메시가 있으면 접촉면으로 취급한다. 수면 착수 모델이 아니다. 공중 항로·자동 실속 회복과 자동 착륙 제어기는 구분되며 지형 회피는 아직 없다.

코어의 정지 평형·제동·조향·이착륙·충돌 회귀 검사와 실제 기체의 성능 검증은 별개다. 이 모델의 반력을 실제 착륙장치 강도 판정에 바로 사용할 수 없으며, 실측 제원·시험 데이터와 합의된 정식 시험 기준을 반영하는 작업이 남아 있다.
