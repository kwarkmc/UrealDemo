# Cessna 208B 기준 다기종 비행역학 확장

2026-11-18 우선순위 변경: 다음은 [착륙 전환 개선·실제 지형 연속 왕복·기체 동작 정밀화](return-landing-plan.md)다. 일반 항로점 포착/선회 잔차/러더 협조는 이후로 미룬다. 아래 A2 실기체 근거 미확보 상태는 유지하며, 새 계획의 연구용 기능 구현과 구분한다.

2026-11-17 최종 사용자 결정: 첫 대형 비행역학 확장 기준을 **Cessna 208B Super Cargomaster**로 지정한다. **King Air 350은 후속 쌍발 확장 후보**, **Thor는 기존 실행·회귀 기준**으로 둔다. 앞선 200kg 초과 단발 무인기 후보 탐색에서 유인 단발 터보프롭을 계산 코어의 개발 기준으로 쓰는 방향으로 변경했다. 무인기 시뮬레이터라는 제품 목표는 유지하며 C208B를 실재 무인기로 표현하지 않는다.

실제로 모의하는 운용 총질량은 200kg 초과이며 최대이륙질량(MTOW), 공허질량, 탑재·연료 구성과 그때의 CG·관성을 별도 기록한다. 장기 목표는 기체별 근거 자료를 적용하는 다기종 고정익이다. 외형이나 질량만으로 모든 기체의 성능을 재현한다는 뜻은 아니다.

현재 상태는 **A1+B 및 C~F의 사용자 승인 연구 가정 범위 구현 완료**다. **A2의 동일 구성 실기체 자료 확보·성능 검증은 미완료**다. 실제 적용은 별도 `c208b-research-assumptions`이며 Thor 회귀를 유지한다. 원래 실기체 자료 기반 계획과 이 연구 범위를 구분한다.

## 원래 실기체 자료 기반 계획 — 비교를 위해 보존

아래 표의 미구현/자료 보류는 원래 **실기체 자료 기반 모델** 기준이다. 위 연구 가정 모델의 완료 상태와 혼동하지 않는다.

판본 기준은 [실기체·공개 공력 자료 조사](aircraft-candidate-research.md)에서 추적한 **Lampton·Valasek의 구형 208B Super Cargomaster 연구 구성**이다. 공개 연구의 추정·계산 계수와 실측 비교를 구분한다. 일반 208, 최신 Grand Caravan EX/PT6A-140, 수상형, 다른 중량·포드·프로펠러 구성의 수치를 섞지 않는다. 해당 연구와 연결되는 엔진/프로펠러·형상 상태·중량·CG·관성이 확정되지 않은 수치는 미확보로 둔다. TigerShark-XP·SIERRA-B는 보조 조사 후보로 내리고 현재 구현 대상으로 선택하지 않는다.

## 작업 범위와 종료선

첫 적용은 C208B의 좌우 대칭, 고정 질량/CG 단발 터보프롭 강체다. **수평 트림 부근의 clean 공중 수동 비행을 먼저 완성**하고, 자료가 있는 형상·추진·지상·자동 운항으로 확장한다. 기존 엘리베이터·에일러론·러더·스로틀을 재사용하되 실제 자료가 요구하는 플랩/스포일러 효과와 작동기 한계를 필요한 단계에서 추가한다. 고정 삼륜기어로 다루며 수납 명령을 지원하지 않는다. 숫자·축·계수의 단위와 근거를 먼저 확인하고 외형 크기로 비행 특성을 추정하지 않는다.

**첫 구현의 종료선은 B**, **첫 공중 모델의 종료선은 A2+B+C1**, **C208B 운용 개발 모델의 종료선은 A2~F**다. 각 단계는 별도 작은 실행 단위로 진행한다. A2 미확보를 이유로 독립적인 B를 멈추지 않고, B 통과를 C208B 적용 완료로 표시하지 않는다. C1은 기본 형상·고정 질량의 자료가 유효한 국소 범위에 한정하며 실속/이착륙은 지원 범위 밖이다.

King Air 350 구현은 이번 A~F에 포함하지 않는다. 향후 엔진별 입력·고장·추력점·페더링·비대칭 공력과 기어/플랩을 별도 설계하고 해당 350 판본의 자료를 확보한 뒤 진행한다. Thor와 C208B를 쓰는 현재 목적 때문에 미리 다중 엔진 배열·빈 플러그인 인터페이스를 만들지 않는다.

### 바로 다음 자료 작업 A2의 산출물

별도 빈 데이터 파일부터 만들지 않고 아래 목록을 기존 조사 문서에 채운다. 확인된 값마다 원문·쪽/표·단위·축·비행 조건·출처 등급을 붙이고, 누락값은 누락으로 둔다.

1. **연구 구성 고정:** Lampton·Valasek의 종/횡/결합 응답 원문을 대조해 어느 자료가 같은 Super Cargomaster 구성인지 확인한다. 단일 트림점의 값과 다른 형상·비행 조건의 값을 구분하고, 2016 Grand Caravan 모델 갱신 논문은 해당 구성이 확인되기 전 참고 자료로만 둔다.
2. **질량·형상 일치:** 해당 연구의 운용 중량·연료/탑재 상태, CG 기준점, 주익/꼬리·접촉 치수, CG 기준 관성 수치를 확인한다. 제원상 MTOW를 논문 트림 중량으로 대신하지 않는다.
3. **C1의 최소 자료:** 종·횡 힘/모멘트·각속도·조종 미계수와 기준면적·길이·축·각도 단위, 조종면 영점·트림 입력, 기준점의 추진 상태를 확보한다. 기존 비선형 식과 의미가 맞지 않는 계수는 식 정의부터 대조한다. 아직 얻지 못한 항을 0으로 채워 완성 모델로 표시하지 않는다.
4. **C2~E 자료 구분:** 엔진/프로펠러·응답·후류의 지원 범위, 플랩/스포일러·접근/착륙 형상·접촉·제동·운용 한계를 확인한다. 고정피치나 단순 전동 추진 가정으로 터보프롭 전체를 대신하지 않는다. 베타/리버스·페더링은 첫 적용에서 보류하며, 이 기능 없이 비교 가능한 비행/제동 조건을 골라 명시한다.
5. **독립 비교 기준:** 트림, 짧은 조종 입력 응답, 상승/활공 등의 비교 자료와 조건을 확보하고 수치/실제 성능 허용오차를 구분한다. 착빙 논문을 사용하더라도 첫 모델은 clean이며 해당 논문의 착빙 배율을 기본 공력에 적용하지 않는다.

A2의 조사 목록 작성과 **C1 적용에 필요한 자료 확보**를 구분한다. 목록은 누락 상태를 포함해 작성할 수 있지만, C1 필수 자료가 없으면 실기체 프로필 적용은 보류하고 B의 합성 시험체 검사만 진행한다. 자료 사용권·출처 확인도 같은 작업에서 수행하며 연락·구매는 별도 명시적 지시 없이 하지 않는다.

| 향후 물리 | 누락 효과·자료·지원 범위를 기록 | 쌍발/제트/VTOL, 연료 소모·이동 CG, 공탄성·플러터·비대칭 실속·스핀, 확률 난류, SIL/HIL·센서 |

판정은 다음 세 가지로 나눈다. B가 끝나도 A~E가 완료됐다고 표시하지 않는다.

- **다음 작업 완료(B):** Thor와 합성 대형 시험체의 기체별 공중 초기화·제어 입력·명시적 step·실패 보존이 코어와 실제 API에서 동작한다. 새 시험체의 지상/자동 운항은 명시적으로 비활성화한다.
- **첫 대형기 개발 모델 완료(A~E):** 출처와 운용 구성이 특정된 200kg 초과 기체 한 대에 대해, 선언한 범위에서 수동 비행·엔진컷·돌풍·수동 활주/이착륙·항로 비행·자동 왕복이 해당 단계의 검사 기준을 통과한다. 미확인 효과는 계속 공개한다.
- **다기종 구조 확인(F):** C208B에 필요한 기능 구현 후 Thor와 C208B를 데이터·기체별 제어 설정으로 선택하고, 상태 격리·원자적 재읽기·서로 다른 지원 범위를 확인한다. King Air 350 같은 새 추진 구성이 코드 수정 없이 지원된다는 뜻은 아니다. 정식 성능 검증 완료는 이 세 판정과 별도다.

## 기존 코드에서 재사용할 것과 막히는 곳

표준 C++의 힘·모멘트 합산, 강체 6DOF, quaternion RK4, ISA, 명시적 시간 진행과 좌표 변환을 유지한다. 외부 비행역학 구현을 가져오거나 감싸지 않는다. 기체별 계산 상태를 분리하고 동일 초기 조건·입력·시간 간격의 재현을 유지한다.

| 현재 구현 | 다기종 적용의 장애물 |
| --- | --- |
| `AircraftParameters.h`의 50개 수치와 질량 0.1~10000kg 입력 범위 | 입력 허용 범위는 기체 성능 지원 범위가 아니다. 공력은 Thor의 한 기준점에서 재구성한 계수다. |
| `FlightSystems.cpp`의 원자적 프로필 재읽기 | 초기 트림이 2600m/19m/s로 고정돼 있다. `FlightScene.cpp`의 초기화도 19m/s를 사용한다. |
| `Navigation.h`, `FlightOperations.h` | 항로 16~24m/s, 이착륙 속도·경로 치수·이득·조향 휠베이스 등이 개발 기체에 맞춰져 있다. |
| `GroundContact.h`와 Unreal 기본 표시 | 1.27m 기체의 바퀴·동체 접촉점, 3초 기어, 마찰·충돌 기준이 고정돼 있다. STL은 물리를 바꾸지 않는다. |
| `serve-api.py`, `uavsim_client.py`, 두 Web UI | 초기 TAS 5~45m/s 등의 범위와 기본값이 여러 경계에 있다. UI 자동 이착륙도 고정값을 보낸다. |
| 국소 ENU, ISA, 강체 공력 | 원점 50km 제한, 대기 높이 근사, 공간 난류·압축성·구조 유연성 미구현은 기체 확대와 별개다. |

## 기체 데이터와 계산의 연결

새 플러그인 체계를 만들지 않고 기존 프로필과 계산 함수를 필요한 단계에서 확장한다. 파일 형식 변경 시 구버전 Thor의 명시적 호환 처리와 잘못된 새 파일의 원자적 거부를 함께 구현한다. 필드·엔드포인트는 해당 단계 구현 때 확정한다.

| 데이터 | 계산에서 사용할 내용·검증 |
| --- | --- |
| 형상·축·기준점 | SI, body FRD(앞·오른쪽·아래), 공력 면적·날개폭·시위, CG·공력 기준점·추력점. STL 좌표는 별도 변환한다. |
| 질량·CG·관성 | 운용 질량, CG 기준 관성 텐서와 곱관성 부호·출처. 텐서의 양의 정부호·주관성 삼각 조건을 검사한다. 첫 대상은 좌우 대칭 기체로 현재 Ix/Iy/Iz/Ixz 표현을 유지한다. 일반 텐서의 Ixy/Iyz는 실제 대상이 요구할 때 추가한다. 다른 기준점에서 주어진 관성은 평행축 정리로 변환한다. 질량 배치 자체가 달라진 경우에는 평행축 변환만으로 새 CG 관성을 만들지 않는다. |
| 공력 | 초기에는 근거가 있는 국소 계수와 유효 범위를 사용한다. 전 영역 확장 시 alpha/beta, 각속도, 조종면, 형상 상태에 따른 힘·모멘트 계수표를 필요한 축부터 추가한다. Mach/Re 의존성은 자료가 있을 때 추가하며 누락 효과는 미지원으로 공개한다. |
| 추진 | 단발 프로펠러의 속도·밀도·스로틀 또는 RPM에 따른 추력·반작용 토크·응답. 추진축과 CG 상대 위치를 사용한다. RPM 자료가 없으면 추력표 모델이라고 명시한다. |
| 작동기·형상 상태 | 기체별 조종면 위치/속도 한계·응답·부호. 플랩·기어는 작동 상태가 실제 공력 데이터 선택과 연결돼야 한다. 표시 애니메이션만으로 공력을 변경하지 않는다. |
| 지상 접촉 | CG 기준 바퀴·동체 접촉점, 조향 구조, 마찰·브레이크·기어 시간·접지 한계. 이후 실측 완충·타이어 모델은 별도 단계다. |
| 운용·제어 | 초기 트림 조건, 유효 속도/고도/받음각 범위, 이착륙 목표, 조종기 이득과 기동 한계. 물리 데이터와 자동조종 설정의 의미를 구분한다. |
| 출처·지원 상태 | 판본·단위·보간 범위·자료 누락·개발 가정과 검증 조건. 지원 범위 밖 입력은 명시적으로 거부하며 표 경계를 몰래 외삽하지 않는다. |

공통 계산은 동압 `q = rho*V²/2`, 공력 `F = q*S*C_F`, 모멘트 `M = q*S*(b*C_l, c*C_m, b*C_n)`를 기본으로 한다. 양력/항력 축에서 정의한 계수는 먼저 body FRD로 변환한다. 기준점 모멘트는 같은 좌표계에서 `M_CG = M_ref + (r_ref-r_CG) × F`로 옮긴다. 추진도 `r_thrust × F_thrust`와 프로펠러 반작용 토크를 별도로 합산해 이중 적용을 막는다.

강체 운동은 `m*(v_dot + omega × v) = F_total`, `I*omega_dot + omega × (I*omega) = M_total`로 유지한다. 첫 모델은 질량·관성이 일정한 강체다. 연료 소모·질량 방출은 시간변화 질량/관성 및 운동량 처리를 설계하고 검사한 뒤 추가한다. 외형 확대나 질량 변경만으로 이 효과를 대신하지 않는다.

## 구현된 B의 계약과 범위

B는 기존 국소 공력·단발 추력 근사와 고정 질량 강체를 유지한 채 초기화 의존성을 제거하는 작업이다. 실제 기체 자료가 없어도 명시적 합성 시험체로 구조 검사를 진행할 수 있다. 그 시험체는 `tests`의 자료로 두고 기본 활성 기체로 배포하지 않는다. A의 실제 기체 자료가 없는 부분은 미확보로 남기며, 실기체 프로필 완성과 실측 비교는 해당 자료 확보 전 완료 처리하지 않는다.

| 항목 | B의 구현 계약 |
| --- | --- |
| 프로필 | 기존 v1 Thor 파일은 그대로 읽고 기존 기본 동작을 유지한다. 확장 프로필은 별도 버전을 명시하고 초기 TAS·타원체고, 공중 초기조건 허용 범위, 지원 운용을 명시한다. 누락 필드를 Thor 수치로 채워 새 기체를 만들지 않는다. |
| 값의 역할 | `reference_speed_mps`는 공력 계수 정의의 기준이다. 초기 TAS, 운용 한계, 항로 목표 속도와 구분한다. 새 초기 속도를 정하려고 공력 기준 속도를 임의로 바꾸지 않는다. |
| 초기화 경로 | 최초 로드·프로필 재읽기·reset·지역 이동의 기본 초기 조건을 같은 프로필에서 가져온다. 사용자가 명시한 초기조건은 유지하되 새 프로필의 지원 범위로 검증한다. 기존 pose/초기조건의 시간·거리 초기화 차이를 임의로 바꾸지 않는다. |
| 재읽기 성공 | 후보 파싱·범위 검증·초기 트림을 모두 완료한 뒤 모델과 상태를 함께 적용한다. 정지 상태, 시간/거리·고장/돌풍·자동조종 초기화, 일정 바람 유지라는 기존 재읽기 계약을 보존한다. |
| 재읽기 실패 | 기존 프로필·지문·위치·자세·시간·입력·환경을 보존하고 오류만 공개한다. 실행 중 재읽기는 계속 거부한다. 재시도하지 않는다. |
| 지원 범위 | 파일 크기·경로·수치 유한성 등 입력 방어와 기체 운용 범위를 별도로 검증한다. API의 넓은 수치 상한을 비행 가능 범위로 사용하지 않는다. 범위는 런타임이 적용한 프로필에서 읽으며 서버가 선택 파일을 따로 읽어 추측하지 않는다. |
| 실패 구분 | 초기조건/명령 범위 밖은 상태 변경 전에 거부한다. 시간 진행 중 모델 계산 범위를 벗어나면 마지막 유효 상태에서 정지·fault를 공개한다. 속도·받음각을 허용값으로 몰래 잘라 진행하지 않는다. 측정 범위와 명시적 개발 근사의 계산 범위는 구분한다. |
| 미지원 운용 | 합성 새 기체의 항로·지상 시작·기어·자동 이착륙은 UI와 직접 API 모두 거부한다. 공중 시험 중 미지원 접촉에 도달하면 Thor 접촉 모델을 적용하지 않고 정지·이유를 공개한다. 기존 Thor 기능은 유지한다. |
| API·클라이언트·UI | 기존 경로와 메서드를 재사용한다. 상태에 적용된 초기 조건·지원 범위·운용 지원/거부 사유를 추가하고 UI는 이를 표시한다. Python에서 같은 상태·오류를 읽을 수 있어야 한다. 새 범용 설정/선택 API는 만들지 않는다. |

공통 `Navigation.h`/`FlightOperations.h`의 속도·이득 확장, 공력표 로더, 새 추진식, 바퀴 형상 변경은 B에 넣지 않는다. B 완료 시 이 항목이 필요한 실제 기체를 지원한다고 표시하지 않는다.

## 단계별 최소 검사와 실행 빈도

검사는 개수·커버리지 비율을 목표로 늘리지 않고 아래 실패를 잡는 데 필요한 사례를 남긴다. 같은 논리를 여러 층에서 반복하는 대신 코어에서는 수치, API에서는 계약·상태 보존, 화면에서는 표시/조작 연결을 확인한다. 실패는 0이 아닌 종료 코드를 반환한다.

공유 코어 헤더 변경으로 기존 검사 전부가 영향을 받으면 관련 코어 검사 범위는 CTest 전체다. 계산 코어 검사 → 필요 시 Unreal Development 빌드 → 실제 API 검사 순으로 실행한다. 변경하지 않은 지도·EOIR·워게임 전체 하네스를 매번 반복하지 않는다. 통과 후 변경·실패·미해결 우려가 없으면 재실행하거나 범위를 늘리지 않는다. 고속화·새 적분기·장시간 난수 시험·자동 성능 벤치마크는 이번 범위가 아니며 실제 수렴/성능 문제가 드러나면 해당 사례부터 검사한다.

UI는 변경 시 HTML/JavaScript 구문·필드/경로 연결·API 표시값을 정적으로 확인한다. 컴퓨터 사용/UI 자동화 중단 결정은 유지한다. 실제 브라우저의 클릭·슬라이더·지원 상태 표시는 사용자가 수동으로 확인할 수 있게 절차를 제공하고, 확인 전에는 화면 직접 조작 검증 완료로 적지 않는다.

## 허용오차·자료 부족·중단 기준

- 수치 검사의 오차는 해석해·독립 계산·단계 축소 수렴과 부동소수점 규모로 정한다. 트림은 속도 유지 화면만 보지 않고 `힘 잔차/(m*g)`와 `모멘트 잔차/(m*g*기준 길이)` 및 조종 입력 한계로 확인한다. 구현과 똑같은 식을 복사한 기대값으로 맞추지 않는다.
- 실제 성능 오차는 출처의 측정 조건·불확도와 사용 목적에 맞춰 먼저 정한다. 자료·오차 기준이 없으면 수치 개발 검사만 완료로 표시한다. 정식 신뢰성·정적·동적 시험은 사용 목적·환경·합격 기준을 별도로 합의한 뒤 수행하며 이번 개발 완료에 포함하지 않는다.
- A의 필수 형상·질량·CG·관성·공력·추진 자료가 빠지면 실제 기체 프로필 확정을 보류하고, 가능한 B/합성 검사는 계속한다. 외형·MTOW·순항속도만으로 실기체 계수를 채우지 않는다. 불확도 범위의 추정값을 쓰는 연구 모델은 명시적으로 분리하고 실측 검증으로 표시하지 않는다.
- 무트림·수치 발산·기체 범위 밖·미지원 운용·불가능한 활주로는 명시적 실패다. 시각적으로 그럴듯하게 보이도록 위치나 물리 상태를 보정하지 않는다. 실패 시점·입력·프로필 지문·계산 간격·오류를 재현 가능하게 기록한다.
- 기존 검사가 깨지면 원인·변경된 계약을 먼저 확인한다. 결과를 통과시키기 위한 허용오차 확대, 근거 없는 계수 조정, 오류 숨김은 하지 않는다. 파일 복구 실패는 성공으로 처리하지 않는다.
- 범위 밖 요구나 새 자료가 나오면 해당 단계의 설계와 검사 기준을 갱신한다. 반복 확인 질문으로 정상 작업을 멈추지 않되 새 실측 기준·지원 범위를 임의로 확정하지 않는다.

## 검사와 남겨둘 경계

- 공통 코어: 해석 가능한 무외력·일정 힘/모멘트, 좌표 부호·모멘트 팔, 에너지·시간 간격 수렴·재현 검사. NASA NESC의 공개 [6DOF 확인 사례](https://nescacademy.nasa.gov/flightsim/2015)는 독립 비교 근거 후보이며 아직 실행/통과하지 않았다.
- 기체별: 합의한 고도·속도·질량에서 트림 잔차·조종 입력·상승/활공·선회·동적 응답을 출처 자료와 비교한다. 자료와 허용오차는 검사 전에 정하고 무근거 허용오차로 실제 성능 합격을 만들지 않는다.
- 기존 Thor 회귀와 새 합성 모델의 수치 검사는 실제 200kg 초과 기체 성능 검증과 구분한다. 내부 검사 통과를 정식 신뢰성·정적·동적 시험 완료로 표현하지 않는다.
- 비대칭 실속·스핀에는 좌우 비대칭/실속 후 공력 자료와 모델 확장이 필요하다. 공탄성·플러터에는 구조 자유도가 필요하다. 현재 강체를 크게 만드는 것만으로 지원하지 않는다.
- 쌍발·제트·비행익·VTOL·천음속·초음속은 첫 단계 지원 약속에 포함하지 않는다. 기체 구성별 힘·모멘트·추진·제어 자료와 검사가 확보될 때 단계적으로 확장한다.
- 임의 계수를 실제 기체 프로필로 만들지 않으며, 아직 새 활성 기체·범용 공력표 로더·추진기 플러그인·새 서버를 추가하지 않는다.
